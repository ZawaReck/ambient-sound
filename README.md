# 外音取り込み (AmbientSound)

耳栓 + Shokz OpenRun Pro で音を聴いたまま、近くの人と会話するための macOS メニューバーアプリ。
イヤホンのマイクで周囲の声を拾い、同じイヤホンへリアルタイムに返す。
Bluetooth が通話用モード (HFP) に落ちて音質が下がってもよい、という前提で「声を聞き取れること」を優先している。

## 構成

- Swift Package (macOS 13+, Swift 6.2 / 言語モード 5)。外部ライブラリなし。
- `Sources/AmbientSound/AudioDevices.swift` — CoreAudio のデバイス列挙・属性取得
- `Sources/AmbientSound/AudioBridge.swift` — 音声転送本体
- `Sources/AmbientSound/AppDelegate.swift` — メニューバー UI、権限、停止処理
- `Resources/Info.plist` — `LSUIElement`（Dock に出ない）、`NSMicrophoneUsageDescription`
- `build.sh` — `.app` を組み立てて ad-hoc 署名

## 採用した音声 API

CoreAudio の **AUHAL (`kAudioUnitSubType_HALOutput`)** を入力用・出力用に 1 つずつ使う。

- `AVAudioEngine` は入力と出力が 1 つの IO ユニットを共有し、別デバイスの組み合わせ（例: Mac 内蔵マイク → OpenRun Pro）がうまく扱えないため使わない。AUHAL ならデバイスごとに独立して指定できる。
- 入力コールバックで取得したモノラル Float32 をメモリ上のリングバッファ（最大約 0.12 秒滞留で古い分を捨てる）に書き、出力コールバックで線形補間してレート差を吸収しつつ読み出す。
- 目標滞留は約 80 ms（クロックのずれは読み出し速度を ±1% 以内で補正して吸収）。入力が追いつかない（アンダーラン）と無音にして再度溜まるのを待つ。
- 安全対策: 起動のたびに倍率 ×0.5 から開始（上限 ×4）、倍率は約 50 ms でなめらかに変化、出力は `0.9·tanh(x/0.9)` のソフトリミッタで ±0.9 を超えない。出力が 1.5 秒以上飽和し続けたらハウリングとみなして自動停止。
- プライバシー: 音声はリングバッファを通るだけで、録音・保存・送信・ログ出力は一切しない。
- Bluetooth はマイクを開くとプロファイルが切り替わり出力側のサンプルレートが変わるため、入力を先に開いて 0.4 秒待ってから出力を構成し、さらにレート変化を検知したら自動で作り直す（10 秒に 5 回以上なら停止）。
- 停止条件: マイク権限なし、入力/出力デバイスの消失（イヤホン切断）、ハウリング疑い、起動失敗。

## ビルドと起動

```sh
./build.sh                 # build/AmbientSound.app を生成
open build/AmbientSound.app
```

メニューバーに耳アイコンが出る。クリックして「外音取り込みを開始」。

## マイク権限

初回の開始時に macOS が許可ダイアログを出すので許可する。拒否した／出なかった場合は
システム設定 > プライバシーとセキュリティ > マイク で「AmbientSound」をオンにする（アプリの警告ダイアログからも開ける）。
ad-hoc 署名のため、再ビルドすると権限が再確認されることがある。

## 入出力デバイスの選び方

- メニューの「入力デバイス」「出力デバイス」から選ぶ。選択は次回起動時にも引き継ぐ。
- 「システム既定」を選べば、システム設定 > サウンド の入力/出力に従う（動作中に既定を変えても反映されない。開始し直す）。
- メニュー上部に現在の入力・出力デバイス名、サンプルレート、遅延の目安、入力レベルを表示する。

## 実機での確認手順

1. OpenRun Pro を Mac に Bluetooth 接続し、耳栓をして装着する。
2. アプリを起動し、入力・出力の両方が OpenRun Pro になっていることをメニューで確認する。
3. 「外音取り込みを開始」。入力レベルのバーが話しかけると動くか確認する。
4. 音量を ×0.5 から少しずつ上げ、向かい合った相手の声が聞き取れるか確認する。
5. 会話を妨げる遅延、自分の声の響き、ハウリング（キーンという音）がないか確認する。
6. 相手の声が拾えない場合は、入力デバイスだけを「MacBook のマイク」に変えて比較する（出力は OpenRun Pro のまま）。
7. 動作中に OpenRun Pro の電源を切る／接続を切り、アプリが停止して通知することを確認する。
8. マイク権限をオフにして開始し、案内ダイアログが出ることを確認する。

## 確認できたこと・できていないこと

確認できた（開発環境でのビルド時点）:
- `./build.sh` でビルド・署名が通る。
- 起動して 3 秒間クラッシュせず動作する。

**未確認（実機・実環境が必要）**:
- OpenRun Pro のマイク入力とイヤホン出力を同時に使えるか、その際の実際の音質・サンプルレート
- 相手の声を聞き取れる品質か／内蔵マイクとの比較
- 遅延の体感、自分の声の響き、ハウリングの有無（遅延の目安値は CoreAudio の申告値で実測ではない）
- マイク権限ダイアログ・拒否時の案内、イヤホン切断時の自動停止の実際の挙動
- Bluetooth プロファイル切替時の自動作り直しの挙動
- メニュー UI の見た目

## 残る制約

- Bluetooth マイク経由では、HFP のコーデック遅延が加わり、遅延は数十〜数百 ms になりうる。実機で許容できるか要確認。
- 自分の声が頭内で響く（骨伝導 + 外音の二重）現象は、この方式では避けられない。
- ノイズ抑制・会話の自動検出・音量の自動調整はない。必要性が分かってから検討する。
- ad-hoc 署名のみ（配布・公証はしていない）。
